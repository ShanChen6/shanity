# C2 — Course database schema

The entire backend now uses TypeORM 1.1, including Course/User entities and
migrations. `DatabaseModule` exports the shared TypeORM `DataSource`. Schema
synchronization and automatic startup migrations are disabled. See
[TypeORM migration and upgrade guide](typeorm.md) for configuration and deployment.

## Migration

`src/database/migrations/202610020002_course_schema.ts` alters the existing `courses` table, preserving
IDs, slugs, ownership, instructor assignments and dependent records. It must run
after the six existing migrations, through the usual `pnpm --filter api db:migrate`.
No application database is migrated automatically by this task.

The PostgreSQL enum `CourseStatus` and TypeScript enum retain all five existing
values as agreed: `DRAFT = 'draft'`, `REVIEW = 'review'`,
`PUBLISHED = 'published'`, `HIDDEN = 'hidden'`, `ARCHIVED = 'archived'`.
The default remains `draft`; unknown enum values now produce PostgreSQL `22P02`.

| Column | Definition |
| --- | --- |
| id | UUID primary key, generated by PostgreSQL |
| title | Required text |
| slug | Required text, existing unique constraint/index |
| description | Nullable text |
| short_description | Nullable text |
| thumbnail | Nullable text |
| status | Required CourseStatus, default draft |
| instructor_id | Nullable UUID, FK_courses_instructor → users.id, ON DELETE RESTRICT |
| published_at | Nullable timestamptz |
| created_at | Required timestamptz, default now() |
| updated_at | Required timestamptz, default now(), database update trigger |
| owner_id | Existing nullable ownership FK, preserved |

`instructor_id` identifies the primary instructor and is separate from ownership
and the existing `course_instructors` assignments. It starts NULL for old courses;
no instructor or role is inferred. No authorization policy is added in C2.
`published_at` also starts NULL: historical publication times are unknown.
Existing `updated_at` values are initialized from `created_at`.

Indexes cover `instructor_id` and `(status, published_at)`. The existing slug
unique index is reused. `Course.instructor` maps a nullable `ManyToOne` relation to
`User` without cascade writes/deletes. User password hashes are excluded from
default TypeORM selects. Both entities map snake_case database columns to camelCase.

The database trigger advances `updated_at` for ORM and direct SQL updates.
Reload a saved entity when its new trigger-generated timestamp is needed.

## Rollback

Only C2 has a reversible Down migration; earlier migrations retain their existing
rollback restrictions. Use `pnpm --filter api db:revert` to revert the latest migration only.

Down preserves course rows and dependent records, restores the text status CHECK
and description default/NOT NULL, and removes C2 columns, indexes, FK, trigger and
enum. **Values in the new columns are lost**, and NULL descriptions become empty
strings to satisfy the previous schema. Back up those values before a real rollback.
Up can be run again afterward.

## Verification

Use an isolated PostgreSQL database whose name ends in `_test`; configure PGHOST,
PGPORT, PGUSER, PGPASSWORD and PGDATABASE before running:

```sh
pnpm --filter api test:course-schema
pnpm --filter api typecheck
pnpm --filter api lint
pnpm --filter api test
pnpm --filter web typecheck
pnpm --filter web lint
pnpm build
```

The database tests build the API and use randomly named schemas. They exercise
fresh TypeORM migrations and upgrading from a frozen legacy SQL fixture, preserving
records in all five statuses. They cover Up/Down/Up, enum/timestamp definitions,
indexes, required fields, uniqueness, instructor FK/deletion restrictions, timestamps
and real TypeORM relation loading. Each test removes only its own schema.

API `typecheck` now includes production source and e2e tests. The previous
Supertest type diagnostics have been fixed during the full TypeORM conversion.
No CRUD or course endpoints are implemented.
